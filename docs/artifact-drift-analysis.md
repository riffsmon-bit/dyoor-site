# HoodYØØR Artifact Drift Analysis

Status: **EXPLAINED — NO EXECUTABLE IMPACT**

This analysis covers the six Foundry JSON artifacts that failed the previous whole-file freeze. The prior files were reconstructed exactly from the rebuilt files and the known compiler bookkeeping values. Each reconstruction hashes to the prior frozen SHA-256; this is stronger than comparing a selected subset of fields.

Machine-verifiable reconstruction is implemented in `scripts/analyze-artifact-drift.js`.

## Exact cause

Foundry artifacts contain compiler identifiers that depend on the compilation unit, even when the contract source and generated bytecode do not change:

- `deployedBytecode.immutableReferences` is keyed by a Solidity AST declaration ID. The key identifies a compiler AST node; the security-relevant immutable patch locations are the `start` and `length` values beneath it.
- `bytecode.sourceMap`, `deployedBytecode.sourceMap`, and the top-level `id` contain compiler source IDs used by debuggers.
- Compiling the complete source graph after the updated Revenue Vault changed those compiler-assigned IDs. It did not change instructions, metadata embedded in bytecode, ABI, storage semantics, or immutable patch locations.

## Field-by-field result

For every affected contract:

| Field | Category | Result |
|---|---|---|
| Contract source SHA-256 | SOURCE METADATA | unchanged |
| ABI | ABI | byte-for-byte unchanged |
| Constructor ABI | ABI | byte-for-byte unchanged |
| Creation bytecode object | EXECUTABLE BYTECODE + embedded compiler metadata | byte-for-byte unchanged |
| Runtime bytecode object | EXECUTABLE BYTECODE + embedded compiler metadata | byte-for-byte unchanged |
| Parsed compiler metadata | COMPILER METADATA / SOURCE METADATA | byte-for-byte unchanged |
| Raw compiler metadata | COMPILER METADATA / SOURCE METADATA | byte-for-byte unchanged |
| Method identifiers | ABI / BUILD METADATA | byte-for-byte unchanged |
| Creation link references | LINK REFERENCES | byte-for-byte unchanged |
| Runtime link references | LINK REFERENCES | byte-for-byte unchanged |
| Immutable patch `start`/`length` groups | IMMUTABLE REFERENCES | semantically and byte-for-byte unchanged |
| Immutable AST key labels | IMMUTABLE REFERENCES / DEBUG INFORMATION | changed compiler IDs only |
| Source-map ranges, jump markers, modifier depths | DEBUG INFORMATION | unchanged |
| Vault source-map source ID | DEBUG INFORMATION | `42` → `58` only |
| Vault top-level source ID | BUILD METADATA | `42` → `58` only |
| Storage layout field in historical/default artifacts | STORAGE LAYOUT | absent in both old and rebuilt files |

The release profile now explicitly requests `storageLayout`. Its canonical hash removes AST IDs while retaining slot, offset, label, type encoding, members, and byte width. This makes storage layout both auditable and invariant to the exact bookkeeping drift identified here.

## Why executable behavior is unchanged

The creation and runtime bytecode objects are identical for each old/rebuilt pair. Those bytecode objects include Solidity’s CBOR metadata suffix, so identical bytecode also proves the embedded compiler-metadata hash is identical. ABI, constructor, link references, and immutable patch offsets are also identical. The only modified values are debugger/build identifiers that are never deployed or evaluated by the EVM.

Whole-file artifact SHA-256 remains useful as a build-output checksum, but it is not the release authority. The new canonical artifact procedure hashes all release-critical fields while excluding only:

- top-level compiler source ID;
- creation/runtime source maps;
- immutable AST declaration ID labels (not their patch locations);
- storage-layout AST IDs (not slot/type semantics).

All exclusions are compiler debug identities. No instruction, ABI entry, constructor input, storage slot, link location, immutable patch location, compiler setting, or source hash is excluded.

The previous artifact approvals are invalidated. The new release freeze requires reproducible whole artifacts under one explicit release compilation scope plus the canonical release-critical hashes.
